```bash
pnpm add @uplide/upspector @uplide/upspector-next
```

Requires Next.js 15.3 or newer and React 19.

<Callout title="Automatic setup">
  `pnpm dlx @uplide/upspector-cli init` installs the packages and makes the
  changes below for you. See [Automatic setup](/docs/frontend/cli).
</Callout>

After these five files, nothing else changes in the app: every server and
browser `fetch` to the backend is captured.

<Steps>
<Step>

### Shared config

One config, used by the server and the browser.

```ts title="upspector.config.ts"
import { defineNextUpspectorConfig } from '@uplide/upspector-next';

export default defineNextUpspectorConfig({
  enabled: process.env.NEXT_PUBLIC_UPSPECTOR === 'true',
  backend: {
    origins: [process.env.NEXT_PUBLIC_API_BASE_URL],
    proxyPath: '/api/proxy', // optional same-origin proxy the browser uses
  },
});
```

A request is captured when its origin is one of `backend.origins`, or when it
is same-origin and its path starts with `backend.proxyPath`.

</Step>
<Step>

### Next config

In development, Next serves Server Component fetches from cache across HMR —
even `no-store` ones — so after an edit the backend is never called and the bar
stays empty. `withUpspector` turns that cache off while Upspector is enabled
and returns your config untouched otherwise.

```ts title="next.config.ts"
import { withUpspector } from '@uplide/upspector-next/config';

export default withUpspector(nextConfig);
// or: withUpspector(nextConfig, { configFile: 'config/upspector.ts' })
```

By default it reads the first `upspector.config.{ts,mts,js,mjs}` in the project
root.

</Step>
<Step>

### Server instrumentation

`register` runs before Next patches `fetch`, so the wrapper sits inside Next's
dedup and Data Cache and only sees real network calls.

```ts title="instrumentation.ts"
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { registerUpspector } = await import('@uplide/upspector-next/server');
    registerUpspector((await import('./upspector.config')).default);
  }
}
```

</Step>
<Step>

### Client instrumentation

Must be synchronous: only synchronous code here is guaranteed to finish before
hydration.

```ts title="instrumentation-client.ts"
import { installUpspectorClient } from '@uplide/upspector-next/client';
import upspector from './upspector.config';

installUpspectorClient(upspector);
```

</Step>
<Step>

### Root layout

Call `openUpspectorScope` **before the first `await`** — Next starts rendering
child segments while a parent layout is suspended, so anything awaited first
would let the page's own requests go uncaptured. Render `UpspectorRoot` after
`children`, inside `Suspense`, so it streams last.

```tsx title="app/layout.tsx"
import { Suspense } from 'react';
import { UpspectorRoot, openUpspectorScope } from '@uplide/upspector-next/server';

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  openUpspectorScope({ profile: process.env.UPSPECTOR_RENDER_PROFILE === 'true' });

  return (
    <html lang="en">
      <body>
        {children}
        <Suspense>
          <UpspectorRoot />
        </Suspense>
      </body>
    </html>
  );
}
```

</Step>
</Steps>

## Scope and opt-out

Server-side capture only applies inside a render. Route handlers (an API proxy
streaming backend responses) and middleware are left alone.

To skip a single call:

```ts
await fetch(`${API}/products`, { upspector: false });
```
