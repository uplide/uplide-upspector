Every integration looks up the collector of the current request through
`AsyncLocalStorage`. Outside a request, or with `enabled: false`, it does
nothing.

## Prisma

With Prisma 7, wrap the **driver adapter**, not the client:

```ts title="src/prisma.service.ts"
import { PrismaPg } from '@prisma/adapter-pg';
import { instrumentPrismaDriverAdapter } from '@uplide/upspector-nest';
import { upspectorOptions } from './upspector';

new PrismaClient({
  adapter: instrumentPrismaDriverAdapter(new PrismaPg(pool), upspectorOptions),
});
```

Each query records its SQL, parameters, duration, kind (`query`, `execute`,
`begin`, `script`), whether it ran inside a transaction and the application
call site. Identical SQL issued more than once in a request is listed under
`duplicates` (top 10, most repeated first), which is how the bar flags N+1 patterns.

## Drizzle

Wrap the database returned by `drizzle(...)`. It works with every driver
(`node-postgres`, `postgres-js`, `mysql2`, `better-sqlite3`, `libsql`, ...):

```ts title="src/db.ts"
import { drizzle } from 'drizzle-orm/node-postgres';
import { instrumentDrizzleDatabase } from '@uplide/upspector-nest';
import { upspectorOptions } from './upspector';

export const db = instrumentDrizzleDatabase(
  drizzle(pool, { schema }),
  upspectorOptions,
);
```

Query builders, relational queries (`db.query.*`), `db.execute(sql)` and
prepared statements are recorded with the same fields as Prisma queries. The
kind is derived from the SQL: `query` for reads, `execute` for writes and
`begin` for transaction starts. `BEGIN`/`COMMIT` rows appear only for drivers
that issue them as SQL (`node-postgres`, `mysql2`); drivers with a native
transaction API (`pglite`, `better-sqlite3`) show just the statements inside.

<Callout>
  The call site is resolved from the stack when the query runs. A plain
  `await db.select()...` starts the query from a microtask, so no application
  frame is left on the stack and the call site stays empty; `.execute()`,
  `.all()` or `.then()` called directly keep it.
</Callout>

## Redis (ioredis)

```ts
import { instrumentRedisClient } from '@uplide/upspector-nest';

const redis = instrumentRedisClient(new Redis(process.env.REDIS_URL));
```

Records the command, key, argument count and duration of every operation.

## Outbound HTTP

```ts
import axios from 'axios';
import {
  installAxiosInstrumentation,
  installFetchInstrumentation,
} from '@uplide/upspector-nest';

installAxiosInstrumentation(axios); // default instance + every axios.create()
installFetchInstrumentation(); // patches globalThis.fetch
```

Records method, URL, status code, duration and errors of calls the backend
makes to other services. The axios integration also patches `axios.create`,
so instances built later — including `@nestjs/axios`'s `HttpService` — are
covered.

## Logs

`UpspectorConsoleLogger` extends Nest's `ConsoleLogger` and mirrors each printed
line into the current request. Console output stays byte-identical, and only
enabled log levels are captured.

```ts
const app = await NestFactory.create(AppModule, {
  logger: new UpspectorConsoleLogger(),
});
// or later: app.useLogger(new UpspectorConsoleLogger());
```

## Custom spans

Time work the built-in integrations do not see — queue producers, background
fan-out inside a request:

```ts
import { getUpspectorCollector } from '@uplide/upspector-nest';

const end = getUpspectorCollector()?.startSpan('pricing:recalculate');
try {
  await recalculatePrices();
} finally {
  end?.();
}
```

The span shows up in the **Timers** tab next to the built-in `pre-handler`,
`handler`, `serialize` and `total` spans.
